# Источники и AI-контур SaleTracker

Обновлено: 23 августа 2026 года.

## Как собираются материалы

Основной механизм — **RSS-ленты изданий**. Лента отдаёт все публикации за
период целиком, поэтому поток предсказуем: 11 источников реестра дают около
250 свежих материалов за пять дней. Веб-поиск для этой задачи не годится — он
возвращает выборку и отвечает неровно: один прогон приносил 8 карточек,
следующий ни одной.

Роль модели изменилась. Она не ищет, а разбирает: получает текст публикаций,
отбирает значимые для поставщиков и закупщиков и оформляет карточки с
проверяемыми цифрами. Адрес карточки обязан совпадать с адресом публикации из
ленты, поэтому сослаться на выдуманную страницу она не может.

Между лентами и моделью теперь работает постоянная очередь PostgreSQL. Сначала
все найденные публикации сохраняются и дедуплицируются по каноническому URL.
Затем воркер забирает небольшую пачку и разбирает каждую статью отдельным
запросом с ограниченной параллельностью. Поэтому таймаут или неверный ответ по
одной статье не отменяет всю пачку и не заставляет повторно оплачивать уже
готовые материалы.

После загрузки текста вычисляется его хеш. Это отсекает синдицированные копии,
даже если они опубликованы по разным адресам. Текст сохраняется до AI-вызова,
так что повторная попытка не нагружает сайт-источник повторно.

Источники без лент (Росстат, ЦБ, пресс-центры сетей) остаются на веб-поиске —
для них он по-прежнему единственный способ.

## Что реализовано

В админке появился раздел «Источники и AI». Исследовательский агент:

1. выполняет web search только по утверждённому белому списку доменов;
2. ищет материалы за выбранный период;
3. принимает только сюжеты с прямой ссылкой на конкретную публикацию;
4. извлекает дату, факты, минимум один числовой показатель, значение для бизнеса,
   теги и оценку уверенности;
5. сервер повторно проверяет домен, прямой путь статьи, временное окно,
   числовой формат показателей и принадлежность тегов каталогу;
6. создаёт карточку со статусом `collected` и пометкой `structural-pass`;
7. в автономном режиме утверждает только карточку выше заданного порога
   уверенности, уже прошедшую все структурные проверки;
8. повторяет временный сбой только для конкретной статьи, после исчерпания
   попыток переводит её в `dead-letter`, а после паузы возвращает в очередь
   только провайдерские ошибки.

При `NEWS_AUTO_APPROVE=false` редактор проверяет первоисточник, сопоставляет
факты, создаёт оригинальный аналитический материал SaleTracker и только затем
переводит его в `approved`.

Разбор RSS-публикаций использует переключаемый провайдер и одинаковую строгую
JSON Schema: OpenAI Responses API либо Perplexity Sonar API. По умолчанию
выбран OpenAI и `gpt-5.6-luna` — модель для экономичной обработки большого
потока; для Perplexity по умолчанию используется `sonar`. Встроенный
`web_search` OpenAI остаётся отдельным резервным режимом только для источников
без RSS.

Каждый успешный ответ AI записывается в `news_ai_usage_events`: входные,
кэшированные, cache-write, выходные и reasoning-токены, провайдер, модель и
стоимость. Для OpenAI цена рассчитывается по тарифу выбранной GPT-5.6 модели,
включая отдельную плату за фактические `web_search_call`; для Perplexity берётся
`usage.cost.total_cost` из ответа. В админке показываются агрегаты за 24 часа и
за всё время. Счётчик включает отфильтрованные статьи и повторные попытки, но не
восстанавливает вызовы, сделанные до его установки.

- [Актуальный выбор моделей](https://developers.openai.com/api/docs/guides/latest-model)

## Принцип доверия

### Приоритет 1 — первичные и ключевые профильные источники

- государственная статистика и регуляторы: Росстат, Банк России, ФАС,
  Минпромторг, Минсельхоз, Роспотребнадзор, Россельхознадзор, Правительство;
- ассоциации и исследования: АКОРТ, АКИТ, Data Insight;
- профильные редакции: Retail.ru, New Retail, Shopper’s, Milknews, Sfera.fm,
  Агроинвестор, Логирус;
- корпоративные пресс-центры: X5, Магнит, Лента, RWB.

Корпоративный пресс-релиз считается первичным источником факта о самой
компании, но не независимой оценкой рынка.

### Приоритет 2 — расширение и перекрёстная проверка

ЕЭК, Союз независимых сетей, РОМИР, INFOLine, MarketMedia, DairyNews,
FruitNews, Meatinfo, Unipack, Fishnews, Логистика.ру, Oborot.ru, РБК,
Коммерсантъ, ТАСС, Fix Price, М.Видео–Эльдорадо.

Если первичный документ доступен, цифра из делового СМИ проверяется по нему.
Закрытый или платный текст можно использовать как сигнал, но не как
единственное основание для материала.

### Приоритет 3 — радар, а не доказательство

Дополнительные отраслевые сайты и Telegram-каналы используются для раннего
обнаружения темы. Telegram New Retail и Логирус внесены в реестр в ручном
режиме: агент не использует пост канала как финальный первоисточник.

Полный машинно-читаемый реестр находится в
`src/features/news-sources/news-source.registry.ts` и отображается в админке.

## Тематическое покрытие

Реестр охватывает:

- продуктовый ритейл и федеральные/региональные сети;
- СТМ и контрактное производство;
- молоко, мясо, рыбу, овощи и фрукты, напитки, бакалею, ингредиенты;
- non-food, электронику и дискаунтеры;
- маркетплейсы, e-commerce и селлеров;
- склады, транспорт, последнюю милю и холодовую цепь;
- упаковку, маркировку, качество и техрегламенты;
- цены, выручку, средний чек, комиссии, инвестиции, маржу и объёмы рынка.

## Редакторские стоп-факторы

Кандидат нельзя утверждать, если:

- URL ведёт на главную страницу, поисковую выдачу или неизвестный домен;
- дата публикации или ключевая цифра не подтверждается в тексте;
- значение для бизнеса подменено выдуманным прогнозом;
- новость основана только на анонимном паблике;
- материал является рекламным заявлением без явной маркировки контекста;
- для одного события создаются несколько почти одинаковых заметок;
- оригинальная статья SaleTracker просто копирует или механически
  пересказывает внешний текст.

## Запуск

В `.env.local` нужно добавить:

```dotenv
NEWS_AI_PROVIDER=openai
OPENAI_API_KEY=...
OPENAI_NEWS_MODEL=gpt-5.6-luna
PERPLEXITY_API_KEY=
PERPLEXITY_NEWS_MODEL=sonar
NEWS_PROCESSING_BATCH_SIZE=8
NEWS_PROCESSING_CONCURRENCY=3
NEWS_PROCESSING_MAX_ATTEMPTS=3
NEWS_PROCESSING_RETRY_DELAY_MS=300000
NEWS_PROCESSING_LEASE_MINUTES=15
NEWS_DEAD_LETTER_RETRY_HOURS=6
NEWS_DEAD_LETTER_REQUEUE_BATCH_SIZE=24
NEWS_AUTO_APPROVE=true
NEWS_AUTO_APPROVE_MIN_CONFIDENCE=0.8
```

Для перехода на Perplexity:

```dotenv
NEWS_AI_PROVIDER=perplexity
PERPLEXITY_API_KEY=pplx-...
PERPLEXITY_NEWS_MODEL=sonar
```

После смены переменных приложение нужно перезапустить. Автоматического
fallback между платными провайдерами нет: он может незаметно удвоить запросы и
стоимость. Ошибка выбранного провайдера возвращает HTTP 502 и помечает cron-job
как failed; если упала только часть пачки, остальные статьи продолжают работу.

`NEWS_PROCESSING_BATCH_SIZE` задаёт объём одного запуска, а
`NEWS_PROCESSING_CONCURRENCY` — число одновременных запросов к модели. Для
увеличения потока сначала повышайте размер пачки; параллельность повышайте
осторожно и только в пределах rate limit провайдера. Пользовательские дайджесты
не создают отдельный AI-запрос: общий проверенный пул фильтруется по тегам и
правилу 80/20, поэтому рост с 30 до 100 подписчиков не умножает AI-нагрузку.

Состояние очереди (`pending`, `retry`, `deadLetter`) видно в `/api/ready` и в
результате cron-запуска.

После перезапуска приложения:

1. открыть `/admin`;
2. выбрать «Источники и AI»;
3. нажать «Собрать реальные новости»;
4. открыть первоисточник каждой карточки;
5. передать подтверждённый сюжет редактору.

При настроенном `DATABASE_URL` кандидаты и редакционные статусы хранятся в
PostgreSQL. Admin API защищён серверной сессией, а автономный сбор запускается
через `/api/jobs/news-ingestion`. Без базы приложение явно остаётся в локальном
деморежиме.
